## 0. 本バージョンの方針（重要）

> **最優先事項は「ハッカソンでローカル動作のデモンストレーションができること」。**
>
> - **デプロイは行わない。** `cds watch` によるローカル実行（http://localhost:4004）のみで完結させる。MTA作成・Cloud Foundryへのデプロイ等は実施しない。
> - **AIはモック実装（パターンB）。** 実LLM（Generative AI Hub）には接続せず、固定値を返すダミー関数で代替する。
> - **後からパターンA（実AI接続）へ設定変更だけで切り替えられる構造**にする。AI呼び出しは関数として分離し、環境変数 `USE_MOCK_AI` で切替える。アプリ本体（画面・API・DB処理）は切替の影響を受けない。
> - **デモに不要な作業はやらない。** 認証、通知、本番DB接続、監視等は対象外。

## 4. サービス・API設計（CAP / OData V4）

CAPがCDS定義からOData V4サービスを自動生成する。標準CRUDに加え、以下のカスタムアクションを定義する。

### サービス定義（srv/inquiry-service.cds 抜粋イメージ）

```cds
using db from '../db/schema';

service InquiryService {
  entity Inquiries        as projection on db.Inquiries;
  entity AssignCandidates as projection on db.AssignCandidates;
  entity Members          as projection on db.Members;

  // 問い合わせ送信（採番＋保存＋AI起動）
  action submitInquiry(
    companyName : String, contactName : String,
    inquiryType : String, priority : String,
    desiredResponseDate : Date,
    subject : String, content : String
  ) returns Inquiries;

  // 承認（1位候補を確定）
  action approve(inquiryID : UUID, memberID : UUID) returns Inquiries;
}
```

### submitInquiry — 問い合わせ送信

**処理フロー**
1. inquiryNo を採番（`INQ-YYYYMMDD-連番`）
2. Inquiries にINSERT（status=`AI分析中`）
3. 完了レスポンスを返す（画面はメッセージ表示）
4. 非同期で `runAiPipeline()` を起動（5章）

### approve — 承認

**処理フロー**
1. 該当Inquiriesを更新（assignedMember, assignedAt, status=`承認済み`）
2. 更新後の問い合わせ＋メンバー情報を取得（Promise.all で並列）
3. Slack通知を非同期送信（`setImmediate`。失敗してもレスポンスには影響しない）
4. 画面へ反映（Fioriが自動リフレッシュ）

## 5. AI処理設計（切替構造）

### 5-1. 切替エントリ（srv/ai-handler.js）

呼び出し側（inquiry-service.js）は常に `ai-handler` の関数だけを呼ぶ。`ai-handler` が `USE_MOCK_AI` を見てモック／実接続を振り分ける。**呼び出し側はどちらが動いているか意識しない。**

```javascript
const useMock = process.env.USE_MOCK_AI === "true";
const impl = useMock ? require("./ai-mock") : require("./ai-real");

// 入出力の形は mock / real で完全に同一
module.exports.analyzeInquiry = (inquiry) => impl.analyzeInquiry(inquiry);
module.exports.assignMembers  = (analysis, members) => impl.assignMembers(analysis, members);
```

### 5-2. パイプライン起動（srv/inquiry-service.js 抜粋）

```javascript
const ai = require("./ai-handler");

async function runAiPipeline(inquiryID) {
  const inquiry = await SELECT.one.from(Inquiries).where({ ID: inquiryID });

  // AI① 分析
  const analysis = await ai.analyzeInquiry(inquiry);
  await UPDATE(Inquiries, inquiryID).with({
    aiSummary: analysis.summary,
    aiAnswer: analysis.answer,
    aiRequiredSkills: analysis.required_skills.join(","),
    aiMissingInfo: analysis.missing_info
  });

  // AI② アサイン
  const members = await SELECT.from(Members);
  const candidates = await ai.assignMembers(analysis, members);
  await INSERT.into(AssignCandidates).entries(
    candidates.map(c => ({ inquiry_ID: inquiryID, rank: c.rank, member_ID: c.member_id, reason: c.reason }))
  );
  await UPDATE(Inquiries, inquiryID).with({ status: "承認待ち" });
}
```

### 5-3. モック実装（srv/ai-mock.js）★本バージョンで使用

```javascript
// AI① 固定の分析結果を返す
module.exports.analyzeInquiry = async (inquiry) => {
  return {
    summary: `${inquiry.subject}に関する問い合わせ。${inquiry.inquiryType}として受付。`,
    answer: "一般的にはトランザクションログ（SM21等）を確認のうえ切り分けを行います。",
    required_skills: ["SAP FI", "ABAP"],
    missing_info: "エラーメッセージの全文と発生時刻"
  };
};

// AI② メンバーDBから簡易ロジックで候補3名を返す（固定でも可）
module.exports.assignMembers = async (analysis, members) => {
  const skills = analysis.required_skills;
  const scored = members
    .map(m => ({
      m,
      hit: skills.filter(s => (m.skills || "").includes(s)).length,
      load: m.currentCases ?? 0
    }))
    .sort((a, b) => (b.hit - a.hit) || (a.load - b.load))  // スキル一致優先→負荷少順
    .slice(0, 3);

  return scored.map((s, i) => ({
    rank: i + 1,
    member_id: s.m.ID,
    reason: `必要スキル${s.hit}件が合致、現在対応件数${s.load}件`
  }));
};
```

## 6. Slack通知設計（srv/slack-handler.js）

### 概要

承認完了後、Slack Incoming Webhook に Block Kit 形式のメッセージを POST する。AI処理と同じく `setImmediate` で非同期実行し、通知失敗が承認レスポンスに影響しない設計にしている。

### 設定

| 環境変数 | 内容 |
|---------|------|
| `SLACK_WEBHOOK_URL` | Slack アプリの Incoming Webhook URL。未設定時は通知をスキップ |

### 通知メッセージ構成

```
┌─────────────────────────────┐
│  問い合わせアサイン通知       │  ヘッダー
└─────────────────────────────┘
  担当者　〇〇 〇〇
─────────────────────────────
  問い合わせ番号　INQ-YYYYMMDD-NNN
  件名　　　　　　〇〇〇〇〇
─────────────────────────────
  会社名 / 担当者名 / 種別 / 優先度 / 対応希望日

  問い合わせ内容
  ▏（本文）
─────────────────────────────
  AI分析結果①
  要約 / 必要スキル / 簡易回答
```

### 実装（srv/slack-handler.js 抜粋）

```javascript
async function notifyAssigned(inquiry, member) {
  const webhookUrl = process.env.SLACK_WEBHOOK_URL;
  if (!webhookUrl) { console.log("[Slack] スキップ"); return; }

  await fetch(webhookUrl, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ blocks: [ /* Block Kit */ ] })
  });
}
module.exports = { notifyAssigned };
```

### 呼び出し側（srv/inquiry-service.js approve）

```javascript
const [updated, member] = await Promise.all([
  SELECT.one.from(Inquiries).where({ ID: inquiryID }),
  SELECT.one.from(Members).where({ ID: memberID })
]);

setImmediate(() =>
  slack.notifyAssigned(updated, member).catch(err =>
    console.error("[Slack] 通知失敗:", err.message)
  )
);
```

## 8. データ設計（db/schema.cds）

```cds
namespace db;
using { managed, cuid } from '@sap/cds/common';

entity Inquiries : cuid, managed {
  inquiryNo            : String(20);
  companyName          : String(100);
  contactName          : String(100);
  inquiryType          : String(20);
  priority             : String(10);
  desiredResponseDate  : Date;
  subject              : String(200);
  content              : LargeString;
  status               : String(20);
  aiSummary            : LargeString;
  aiAnswer             : LargeString;
  aiRequiredSkills     : String(200);
  aiMissingInfo        : LargeString;
  assignedMember       : Association to Members;
  assignedAt           : Timestamp;
  candidates           : Composition of many AssignCandidates on candidates.inquiry = $self;
}

entity AssignCandidates : cuid {
  inquiry  : Association to Inquiries;
  rank     : Integer;
  member   : Association to Members;
  reason   : LargeString;
}

entity Members : cuid {
  memberNo     : String(10);
  name         : String(100);
  skills       : String(200);
  domain       : String(100);
  currentCases : Integer;
  status       : String(10);
}
```

```json
{
  "cds": {

      "db": { "kind": "sqlite", "credentials": { "url": ":memory:" } },

  },
  "scripts": {
    "start": "cds-serve",
```

## 11. 将来パターンAへの切替手順（時間が余った場合のみ）

アプリ本体（画面・API・DB処理・呼び出し側）は無修正。

1. SAP BTPで SAP AI Core（Extendedプラン）インスタンスを作成
2. サービスキーを取得し `.env` に `AICORE_SERVICE_KEY=<JSON>` を設定（または `cds bind`）
3. `srv/ai-real.js` の2関数を実装（入出力の形はモックと同一に保つ）
4. `.env` を `USE_MOCK_AI=false` に変更
5. `npx cds watch --profile hybrid` で起動

> 切替後もデプロイは不要。「ローカル実行＋AI呼び出しのみクラウド」で動作する。
