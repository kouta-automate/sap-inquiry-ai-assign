# テストデータ定義
## 問い合わせ受付・AI仮アサインシステム（ローカルデモ版）

デモの説得力を左右する初期データ。Members は起動時にシード投入する。
問い合わせ例はデモ当日に入力するサンプル（暗記用）。

## 3. モックAI①の固定レスポンス（参考）

`ai-mock.js` が返す内容。種別ごとに分岐させてもよいが、デモでは下記1パターンでも十分。

```json
{
  "summary": "FI転記処理で実行時エラーが発生し、月次決算前で緊急対応を要する問い合わせ。",
  "answer": "重複キーエラーの可能性。SM21/ST22でダンプ詳細を確認し、該当テーブルのキー重複を調査してください。",
  "required_skills": ["SAP FI", "ABAP"],
  "missing_info": "ダンプの完全なスタックトレースと再現手順"
}
```

## 4. 注意

- ID（UUID）は固定値にしておくと、承認アクションのテストやデバッグが楽になる。
- インメモリSQLiteのため、再起動でMembers以外（問い合わせ）は消える。Membersはシードから毎回復元される。
